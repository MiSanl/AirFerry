## v1.2.0

本版修复 v1.1.6 大文件分段审计发现的完整性、资源占用与发布身份问题。descriptor-v4 尾部新增完整根文件 SHA-256，因此大文件分段需要发送端与接收端同时升级到 v1.2.0；普通 descriptor-v3 传输继续兼容。

### 主要修复

- 发送端增量哈希完整大文件，每个分段同时携带整文件摘要和本段摘要；Android、Windows、网页端冻结根摘要并在最终导出前重算，拒绝混合不同文件修订版的合法分段。
- v1.1.6 未完成的大文件账本因缺少根摘要不能安全续传，升级后会清除并要求重新扫描；普通文件与已完成历史不受影响。
- Android/Windows 大文件任务增加可用空间保护，完成文件通过同卷原子移动进入内容地址库；根任务派生稳定历史 ID，发布中断后可幂等续提且不重复建记录，避免常态 2× 磁盘占用。
- 网页端优先流式写 File System Access；无该 API 的 Blob 回退限制为 64 MiB。普通恢复结果使用 transferable buffer，文字解析不再解码后重新编码，bundle 条目改用共享视图。
- 选择页允许超 256 MiB 的单文件自动分段，但硬性阻止超限文字/多文件包；bundle 产品上限为 4096 个文件。
- 发布脚本固定校验 Android 发布证书和 Chrome 扩展公钥，不再自动生成 Chrome 私钥。Windows CI 必须从指定现有 tag 构建并验证 tag、提交与包版本一致。
- 新增跨项目质量 CI，覆盖 Rust format/test/clippy、浏览器 TypeScript/WASM/receiver build 与 Android 单测。

### 本批补充修复（重新构建覆盖 prerelease）

- **发送端压缩率显示修复**：分段大文件此前只取第一个分段的压缩长度做压缩率（被低估约段数倍，如 6 段文件显示 19% 实为 94%），现改为累加整条压缩流各分段长度。
- **发送端每段帧数/时间估算修复**：修复压缩率改动引入的回归——分段时「每段预计帧数/时间」误用整条压缩流大小计算（高估约段数倍），现按单段字节计算，非分段行为不变。
- **Android 接收端压缩后大小显示修复**：改用描述符真实值（分段为整条压缩流 `root_original_size`，单对象为 `compressed_size`），不再用线上含冗余符号字节；分段时新增「第 N/M 段」实时显示。
- **Android 重扫已完成段立即跳过**：描述符确认后识别已完成段（内存账本优先、磁盘历史账本兜底），重扫已完成段不重传整段，仅状态栏白字提示。
- **Android APK 体积优化**：Release 开启 R8 混淆 + 资源裁剪，剥离 `material-icons-extended` 等 3.2 万个未用图标类与依赖死代码，APK 从约 47 MB 降至约 6.1 MB（dex 44.7 MB → 2.6 MB）。JNI 边界与 `org.json` 反射已加 keep 保护。
- **Android 恢复结果页常亮**：`ReceiveDetailActivity` / `ReceiveTextActivity` / `ReceiveBundleActivity` 补 `FLAG_KEEP_SCREEN_ON`，避免恢复成功瞬间系统超时接管导致屏幕变暗。
- **web 接收端性能提醒**：因浏览器摄像头管道 + JS/WASM 解码限制，接收端顶部提示建议使用 Android / Windows 原生端。
- **移除跨项目 quality CI**：rust/browser/android 均可在本地构建与测试，不再走 GitHub Actions；仅保留 Windows 发布 CI（`.github/workflows/windows.yml`）。
